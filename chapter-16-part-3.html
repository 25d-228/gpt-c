Chapter 16 · Part 3 — Full-prefix generation and executable checks

Part 1 established immutable weight ownership and a reusable forward workspace. Part 2 loaded weights without a trainer and defined exact sampling rules. This part connects them to raw byte files and checks the complete path. All commands run from the root of the Chapter 16 companion.

A bounded generation request

The application accepts ten arguments after the executable:

CONFIG specifies the model geometry expected in the version-1 checkpoint. It also contains training batch/time fields because we reuse the configuration-file format; generation uses one sequence and an explicit capacity instead. The printed config_time is the value from that configuration file, not a context length inferred from weights. The loader checks the saved trainer metadata for coherence but does not import its batching or random state.

PROMPT is a nonempty binary file. Each byte becomes the same integer ID in the 256-entry vocabulary. No token is inserted before it. In particular, the application does not invent a beginning-of-text token, treat zero as an end marker, or require a terminal newline. Generated bytes use the same identity mapping.

CAPACITY bounds the complete transcript, including the prompt and all NEW requested bytes:

1\le P_{\mathrm{prompt}},\qquad P_{\mathrm{prompt}}+N_{\mathrm{new}}\le C.

Here P_{\mathrm{prompt}} is the number of prompt bytes, N_{\mathrm{new}} is the requested count, and C is capacity. These counts are distinct from the parameter count P used earlier. We require 1\le C\le4096 and 0\le N_{\mathrm{new}}\le4096, then impose the tighter combined bound. Allocation budgets can reject a large capacity even within that numerical range. No prefix is silently dropped; there is no sliding window.

With prompt length three and two requested tokens, forward runs on lengths three and four. The resulting file has length five. The last generated byte does not need another forward call unless another token is requested. Requiring the whole output to fit capacity is a simple application policy; it deliberately avoids an exceptional “one last byte beyond capacity” case.

A zero-new-token request is valid. It still checks the model checkpoint and prompt, then copies the prompt into a new output file without calling forward or consuming the sampling RNG. The policy is explicit rather than an accidental special case in the loop.

Read bytes and create only a new output

Create app/generate.c. The decimal parser checks overflow before multiplying by ten. It rejects negative signs and nondecimal characters rather than allowing a large unsigned conversion to conceal an invalid request.

The prompt reader reads at most capacity bytes and probes for one extra byte. An oversized prompt is an error, not a truncated prefix. fread returns a byte count; a NUL inside those bytes has no special meaning.

The output routine uses "wbx": binary output with exclusive creation. The fopen mode documentation describes the C11 x flag's refusal to open an existing file. We use it instead of a separate existence check followed by a truncating open. This does not make the surrounding path safe against hostile concurrent directory changes; use an ordinary controlled output directory.

fwrite can appear successful while buffered bytes have not reached the file. Therefore fclose is also checked; it flushes buffered output and can report an error, as documented by Apple's C library fclose reference. The stream must not be reused after close, including a failed close.

Only a newly created incomplete output is removed. An existing file is never opened for writing and is never removed on that error path. Removal itself is best effort: if the filesystem refuses it, inspect the named output before trying again. This small output helper does not promise checkpoint-style replacement, power-loss durability, or safe operation against concurrent writers.

The main routine computes the whole bounded transcript before opening its output. A bad checkpoint, failed allocation, invalid prompt, or numerical error therefore creates no output file. This also means it is not a streaming terminal application; all output bytes remain in the bounded bytes allocation until successful computation.

Read the loop's indexing carefully. length - 1 is the row that predicts position length. The selected ID is written to ids[length] and bytes[length], and only then is length incremented. The earlier combined-capacity check proves that both writes are in bounds. This is a full-prefix reference path: no DlInference field remembers which earlier bytes were processed.

The fixed budgets are 128 MiB of weight floats, 512 MiB of workspace floats, and 512 MiB of checkpoint bytes. They are separate limits, not a claimed total process-memory bound. The application checks their allocations and all size multiplications. The owner directory, positions, frequencies, token arrays, library buffers, and executable also use memory.

All owned objects start empty. The single done path can release any partially constructed set: destroy the workspace before the weights it borrows. config_batch is parsed for format compatibility but does not allocate a batch. The score tensor contains one row regardless of prefix length. Greedy mode accepts a positive temperature argument for a uniform command shape but does not use it and does not draw from rng.

There are two outputs with different contracts. OUTPUT receives exact raw bytes, including any NULs, invalid UTF-8, or control characters. Standard output uses the existing dl_bytes_fprint escaping routine and reports numeric payload sizes. A terminal-display failure can occur after the complete raw file has been written; the error message does not falsely claim that no output exists.

Compare storage schedules before interpreting prose

Good-looking text is not a numerical reference. We first compare inference logits with the existing training forward graph using the same initialized weights. This isolates the changed storage schedule, selected-row projection, and owner construction. Both paths reuse already-tested numerical operators; the comparison is independent of workspace scheduling, not an independent implementation of every transformer equation.

Create tests/test_inference.c. It uses tests/training_fixture.h, supplied in full in Chapter 15 and retained in this companion. That header defines TrainingFixture, complete create/destroy/equality helpers, and the CHECK, OK, and STATUS macros. These macros branch to the local cleanup label on failure; they are not assert calls compiled out in a release build.

The first function uses a two-term tolerance,

|a-b|\le 2\times10^{-6}+2\times10^{-5}|b|,

while explicitly rejecting non-finite values. There are three head-sharing configurations, two matrix backends, and four prefix lengths: 3\times2\times4=24 cases. The length sequence 1, 17, 3, 5 grows and then shrinks to expose a view mapped using stale capacity offsets. Filling workspace with NaNs makes uninitialized dependencies visible. Padded destination rows have sentinel values outside their logical columns.

Each case compares every output row, the last row alone, a middle subset, and a shorter causal prefix. Computing the same early row with or without a later token must agree. It then checks that the source model's gradients and revision are unchanged and executes its pending backward pass. An inference optimization must not consume or overwrite someone else's training tape.

Next check ownership and failure boundaries. The deliberately injected NaN in a live weight owner is only an isolated test fixture; mutating loaded weights behind a workspace is not a supported API. Restoring it and rerunning verifies that scratch left by a failed call does not create hidden cross-call state. The final call succeeds after destroying the source training model because DlWeights owns an independent copy.

The checkpoint tests need two small helpers. rejects_file checks both the error and the untouched empty destination. Returning an error after publishing a half-loaded owner would still violate the loader contract.

The import test performs a real C training update, saves its version-1 checkpoint, and compares every loaded weight bit-for-bit with the trainer. It then compares final-row logits. Header offsets below refer to the exact little-endian format defined in Chapter 15, not offsets into a compiler's native structure.

There are 18 mutated header/directory/trailer positions plus three invalid floating-point payloads: a NaN weight, a NaN first moment, and a negative second moment. Even discarded optimizer payloads must obey the file format. Six truncations, an extra trailing byte, mismatched configuration, a nonempty output owner, and insufficient budgets are also rejected. The final load uses the exact file-byte budget.

Finally, make choices repeatedly rather than compare only an isolated forward call. Each of eight generated positions obtains logits from the inference workspace and the training forward path on the same growing prefix. Sampled mode uses two equal RNG states. Greedy mode uses neither state. Two backends and two policies give 8\times2\times2=32 matched choices.

The dummy targets exist only because the reference training API also computes a loss. They do not enter the forward logits. This test does not add targets or a training tape to the real generator.

The small model's vocabulary is 16 in the scheduling tests, while the checkpoint test uses the actual 256-byte training format. The inference operators therefore are not intrinsically limited to bytes; the current checkpoint writer and command-line application are. Larger pretrained vocabularies require their own validated import and tokenizer path later.

Exercise the application as a process

Create tests/test_generate_cli.py. Python here orchestrates executables and constructs diagnostic bytes. It never evaluates the model. zero_weight_payload produces a valid-format asset with all weight floats zeroed; the C generator must still execute every operation to obtain its logits.

The header's parameter count is at byte 72; each directory entry contains 64 name bytes and three eight-byte integers before its weight floats. Zeroing only those float ranges leaves the checkpoint geometry, finite moments, and trailer intact. This is a test-asset transformation, not a new public checkpoint-editing API.

The test trains for 12 updates, then deletes the original dataset files before generation. This establishes that importing weights does not secretly reconstruct a trainer from external data. It tests same-seed replay, backend agreement on this fixture, unchanged earlier output when requesting a longer continuation, greedy RNG isolation, zero-new-token behavior, and rejection without overwriting an existing file.

A binary prompt 00 80 ff 41 is kept exactly. Zero weights give tied zero logits, so the lowest-ID greedy rule produces three NUL bytes. Their presence is checked in the raw file, not by a text decoder. The diagnostic terminal rendering is separately checked for escaped ASCII.

On POSIX systems with Python's resource module, the test imposes a three-byte file-size limit in the child process and ignores SIGXFSZ. The attempted seven-byte write must report its actual write/close failure and remove the new incomplete file. This is a real operating-system failure, not a mocked fwrite return. The test prints an explicit skip on platforms without that module.

Same-seed output is conditional on the same logits and arithmetic behavior. This fixture's two backends produce the same sequence, but that observation is not a universal cross-platform bitwise-generation guarantee. If a small numerical change moves a draw across one categorical boundary, the next input changes and later text can diverge. Inspect logits and probabilities before blaming the random generator.

Interpret the payload report

For this pilot at C=64, D=32, K=16, F=80, and H_q=4, the workspace formula from Part 1 gives

7(64)(32)+3(64)(16)+3(64)(80)+2(4)(64)^2=65{,}536

float elements, or 262,144 bytes. There is no multiplication by the number of blocks because the block scratch is reused after each residual result is committed to hidden.

Retained numerical payload Elements Bytes on this configuration
Unique weights 29,856 floats 119,424
Inference arena 65,536 floats 262,144
Requested last-row logits 256 floats 1,024
Sampling probabilities 256 doubles 2,048
Absolute positions 64 size_t values 512 on a 64-bit host
RoPE inverse frequencies 4 doubles 32

The first four lines are printed by the application. This is allocation accounting, not a resident-set measurement. Directory records, both prompt/ID buffers, allocator overhead, stacks, executable pages, and library buffers are outside these rows. Checkpoint reading retains only a small decode/discard buffer in addition to the eventual weight owner, but still reads and validates the existing training file.

For the 2,885,888-parameter small configuration, the weight payload is 11,543,552 bytes. At capacity 128 its reusable float workspace contains 786,432 elements, exactly 3 MiB. Those are dimensions evaluated in the same formulas, not measured M4 memory figures or a new large-model generation run.

The quadratic score/probability term is still present. Reusing one layer's materialized attention matrices removes the training tape's layer multiplier but does not make memory linear in capacity. Every generated token also recomputes all previous projections and feed-forward rows. These are deliberate limitations of the reference path, not hidden optimizations.

Diagnose five plausible mistakes

Make each change in an isolated copy, rebuild the named test, observe the failure, and restore the correct code. Memory sanitizers complement these numerical and state checks; they do not recognize a mathematically wrong but in-bounds row or interval.

Wrong output row. In dl_inference_forward, change selected.offset += first_row * selected.ld to add zero. test_inference fails last-row versus full-output comparison. The decoder's earlier layers can be entirely correct while the generator repeatedly samples the wrong prediction row.

Inclusive upper endpoint. In dl_categorical, change target < cumulative to target <= cumulative. test_sample fails the exact 0.25 boundary probe: the boundary belongs to the next interval. Random smoke tests may miss a measure-zero real boundary, while the actual finite RNG and test inputs can represent it exactly.

Last-ID greedy ties. In dl_greedy, replace the strict maximum comparison with >=. The equal-maxima fixture fails because a later ID replaces the specified lowest ID. The zero-weight CLI fixture is an additional direct consequence: all logits tie and must produce byte zero.

Scale before shifting. Replace the exponential argument with logits[i] / temperature - maximum / temperature, widening as needed. The isolated test run fails the exact common-shift fixture first. More generally, separately dividing large equal logits by a tiny temperature can produce infinity - infinity; subtracting finite widened logits first avoids that undefined difference. A stable formula must preserve its evaluation order, not only its symbolic appearance.

Blindly skip discarded moments. Replace the first-moment float_values decoding call in the weight loader with discard_bytes. The damaged-first-moment fixture fails because malformed numerical payload is now accepted. “Not retained for inference” does not mean “excluded from format validation.” The loader does intentionally treat corpus payload as arbitrary bytes; it is not supposed to validate UTF-8 or reconstruct text samples.

All five isolated variants failed their explicit checks in sanitizer builds without an AddressSanitizer or UndefinedBehaviorSanitizer report in the Linux runs. That result illustrates the division of responsibility: the memory accesses were legal, while the output contract was wrong.

What is established

The generator now has its own weight owner, bounded reusable scratch, explicit requested logits, and a selection state independent of the trainer. It loads existing checkpoints without allocating parameter gradients or optimizer moments, writes exact byte output, and gives reproducible choices under unchanged logits and RNG state. The tests distinguish numeric equivalence, file-format acceptance, state preservation, and byte I/O rather than treating one successful sentence as proof of all four.

The next chapter keeps this full-prefix implementation as its reference. It adds per-layer key/value history, prefill, and one-token decode calls, with a committed length that advances only after a complete successful step. The current transient attention scratch is not that cache.
