## A byte is a vocabulary entry, not necessarily a character

Our small model has vocabulary size $V=256$. Its token ID is the numerical value of an eight-bit byte, from 0 through 255. There is no lookup-based tokenizer and no extra beginning, ending, unknown, or padding ID. In particular, zero is an ordinary byte value, not a signal to stop reading.

A Unicode code point is a different object. For the string `Aé中`, strict UTF-8 encoding produces:

| Code point | UTF-8 bytes in hexadecimal | Byte-model IDs in decimal |
|---|---|---|
| `A`, U+0041 | `41` | 65 |
| `é`, U+00E9 | `C3 A9` | 195, 169 |
| `中`, U+4E2D | `E4 B8 AD` | 228, 184, 173 |

This is three code points but six byte tokens. UTF-8 uses one to four bytes for a code point; a displayed character can itself involve more than one code point. The Unicode Consortium's [encoding FAQ][unicode] explains this distinction. The pretrained model's tokenizer in a later chapter will use a different mapping. Its integer IDs must not be interpreted as byte values merely because both interfaces use integers.

We do not normalize Unicode, replace unfamiliar characters, remove carriage returns, strip whitespace, or discard embedded zero bytes. The asset preparer receives a Python `str`, encodes it strictly as UTF-8, and adds the documented separator. The C loader then preserves the resulting file exactly. That is preservation relative to the record's text field, not a claim that we recovered the original bytes of the remote Parquet representation.

A sampled window may begin in the middle of a multibyte UTF-8 encoding. That is valid for this byte model. Its first token has less character context, but its integer value is still valid. Similarly, generated bytes need not form valid UTF-8. Raw output and human presentation must remain separate; a lossy terminal-decoding choice must never alter the training bytes.

## Derive the target shift before writing the loop

Let a file contain $N$ bytes, indexed $c_0,\ldots,c_{N-1}$. A sequence has $T$ input positions. Starting at byte offset $s$, define

$$
x_t=c_{s+t},\qquad y_t=c_{s+t+1},\qquad 0\leq t<T.
$$

The final input is $c_{s+T-1}$, but its target is $c_{s+T}$. Therefore the last address must satisfy $s+T<N$. There are exactly

$$
W=N-T
$$

valid starts, numbered $0$ through $W-1$, provided $N>T$. A file with exactly $T$ bytes is too short. A file with $T+1$ bytes has **one** possible start, not zero and not two. We use subtraction after checking the ordering, rather than form an unchecked `s + T + 1`.

Take eight bytes `ABCDEFGH`, $T=3$, and two consecutive rows:

| Batch row | Start | Inputs | Targets | Target byte offsets |
|---|---:|---|---|---|
| 0 | 0 | `ABC` | `BCD` | 1, 2, 3 |
| 1 | 3 | `DEF` | `EFG` | 4, 5, 6 |

The byte `D` is both the first row's last target and the second row's first input. That is intentional. Targets have not been duplicated. Byte `H` at offset 7 remains an unscored target in this particular full-batch traversal. We do not create a fictitious `H -> A` transition by wrapping around the file.

For batch size $B$, both arrays are dense shape $[B,T]$ with $M=BT$ entries. Their flattened address is `row * time + t`. The `starts` array has $B$ entries and records each row's source offset; it is useful for debugging, but it is not passed to the model. The model's RoPE positions still run from 0 through $T-1$ within each independent training sequence. A file byte offset is **not** an inference-cache position.

The learning objective is the mean next-byte loss

$$
\mathcal L=-\frac{1}{BT}\sum_{b=0}^{B-1}\sum_{t=0}^{T-1}
\log p_\theta\!\left(y_{b,t}\mid x_{b,0},\ldots,x_{b,t}\right).
$$

Here $\theta$ denotes the model parameters, and $p_\theta$ is the probability obtained from that row's logits. The causal mask already prevents access to future **inputs**. Target shifting does not replace the mask, and the mask does not perform target shifting. The data layer supplies the shift exactly once; the model and loss must not shift again. Loss averaging remains Chapter 5's single division by $BT$.

## Give the file and the batch different owners

`DlByteData` owns the loaded bytes. `count` is the number of valid bytes; `capacity` is the allocation size. We allocate the requested cap once rather than seeking to estimate a file size and then trusting that estimate. This uses more memory for tiny files but keeps the read bound and failure path simple. No terminator is added.

`DlByteBatch` owns one array of `size_t` values, divided into input IDs, target IDs, and starts. Its views do not own their memory. A filled batch is a copy, not a collection of borrowed file pointers: after filling, it does not depend on the data allocation's lifetime. Further sampling still needs the file owner. After a successful model forward, the tape has copied the IDs again, so the caller can refill the batch before backward.

The batch allocation contains $2BT+B$ `size_t` values. With $B=2$, $T=128$, and eight-byte `size_t`, that is $514\times8=4112$ bytes. These are ordinary host integer arrays, not a float tensor. Loading both maximum-sized files reserves 17 MiB of byte payload. Neither number includes allocator, standard-I/O, model, or process overhead.

Create the public interface. A caller must use the constructors, keep metadata unchanged, avoid copying live owners, and supply independent objects. As in earlier chapters, the functions do not try to validate arbitrary forged pointers or detect every possible alias between unrelated C objects.


```c title="include/dl/data.h"
#ifndef DL_DATA_H
#define DL_DATA_H

#include "dl/common.h"
#include "dl/rng.h"
#include <stdio.h>

typedef struct {
    unsigned char *bytes;             /* Owns capacity bytes; count are valid. */
    size_t count, capacity;
} DlByteData;

typedef struct {
    size_t *storage;                  /* Sole owner: 2*count + batch elements. */
    size_t *ids, *targets, *starts;    /* Views into storage, not separate owners. */
    size_t batch, time, count;        /* count = batch*time. */
} DlByteBatch;

/* Empty {0} destinations only. Failure leaves owners unchanged. No live owner
 * copies or metadata edits. No concurrent file mutation or calls. The byte
 * loader accepts arbitrary bytes, including 0, and requires at least two.
 * limit bounds the sole payload allocation, not stdio/process memory.
 * read borrows a blocking stream at its CURRENT position and consumes it even
 * on failure; it never closes it. load opens "rb" and checks close before commit.
 * DL_STATE: I/O failure/nonempty owner; DL_RANGE: short/over-limit content. */
DlStatus dl_bytes_read(DlByteData *out, FILE *stream, size_t limit);
DlStatus dl_bytes_load(DlByteData *out, const char *path, size_t limit);
void dl_bytes_destroy(DlByteData *data);
DlStatus dl_byte_batch_create(DlByteBatch *out, size_t batch, size_t time);
void dl_byte_batch_destroy(DlByteBatch *batch);

/* Data, batch, RNG, cursor, and outputs occupy independent storage. Require
 * constructed unmodified owners and data.count > batch.time. IDs/targets are
 * dense [batch,time], values 0..255; starts contains source byte offsets.
 * sample draws starts uniformly WITH replacement, commits explicit RNG state,
 * and permits overlap inside this ONE file. Preflight failures change nothing.
 * next produces full consecutive batches, advances cursor by batch.count, and
 * never wraps. End: DL_OK, *has_batch=0, unchanged cursor/batch. Drop the final
 * incomplete batch; report its unscored target count. No padding/special IDs. */
DlStatus dl_byte_batch_sample(const DlByteData *data, DlByteBatch *batch,
                              DlRng *rng);
DlStatus dl_byte_batch_next(const DlByteData *data, DlByteBatch *batch,
                            size_t *cursor, int *has_batch);
/* Quoted ASCII presentation only; never a transformation of training bytes.
 * Escape controls, non-ASCII, backslash, quote. I/O failure can leave a partial
 * display. Does not flush or close the borrowed stream. */
DlStatus dl_bytes_fprint(FILE *stream, const unsigned char *bytes, size_t count);

#endif
```

`FILE *` is an opaque standard-library stream handle declared by `<stdio.h>`. The pointer can be borrowed without transferring its lifetime. This is why `dl_bytes_read` and `dl_bytes_load` have different contracts: the first consumes an already-open stream without closing it; the second opens and closes its own stream. A failure can preserve the output owner while still consuming input bytes. “Output unchanged” does not mean that an external stream can be rewound automatically.

There is also an important distinction between an **empty owner** and an **empty file**. `{0}` is the required construction state for an owner. A zero-byte file is rejected because it cannot supply even one input/target pair. A file with two or more bytes can be loaded, but a later batch with a larger $T$ may still be rejected.

## Read a bounded binary stream without silent truncation

Begin `src/data.c` with the imports, compile-time requirements, and owner helper. `CHAR_BIT` is the number of bits in a C byte. The native Mac target has eight-bit bytes; the assertion rejects an incompatible implementation rather than silently changing the vocabulary. `SIZE_MAX <= UINT64_MAX` makes conversion of a validated sampling bound to `uint64_t` exact.


```c title="src/data.c"
#include "dl/data.h"

#include <limits.h>
#include <stdlib.h>

_Static_assert(CHAR_BIT == 8, "byte IDs require 8-bit bytes");
_Static_assert(SIZE_MAX <= UINT64_MAX, "sample bounds must fit uint64_t");

static int data_empty(const DlByteData *d)
{
    return d->bytes == NULL && d->count == 0 && d->capacity == 0;
}
```

Destruction is repeatable for an empty owner. The read routine constructs a private candidate, reads at most `limit` payload bytes, and commits the candidate only after every check succeeds.

`fread(ptr, 1, limit, stream)` requests `limit` objects of size one, so its result is a **byte count**. A short result can mean end-of-file or an I/O error; the [standard-I/O reference][fread] requires the caller to distinguish those with `feof` and `ferror`. Merely checking that the result is nonzero accepts truncated or failed reads.


```c title="src/data.c"
void dl_bytes_destroy(DlByteData *d)
{
    if (d == NULL) return;
    free(d->bytes);
    *d = (DlByteData){0};
}

DlStatus dl_bytes_read(DlByteData *out, FILE *stream, size_t limit)
{
    if (out == NULL || stream == NULL || limit < 2) return DL_ARGUMENT;
    if (!data_empty(out)) return DL_STATE;
    DlByteData candidate = {0};
    candidate.bytes = malloc(limit);
    if (candidate.bytes == NULL) return DL_ALLOC;
    candidate.capacity = limit;
    candidate.count = fread(candidate.bytes, 1, limit, stream);
    DlStatus status = DL_OK;
    if (ferror(stream)) status = DL_STATE;
    else if (candidate.count == limit) {
        /* Distinguish exact capacity from a silently truncated longer file. */
        int extra = fgetc(stream);
        if (ferror(stream)) status = DL_STATE;
        else if (extra != EOF) status = DL_RANGE;
        else if (!feof(stream)) status = DL_STATE;
    } else if (!feof(stream)) status = DL_STATE;
    if (status == DL_OK && candidate.count < 2) status = DL_RANGE;
    if (status != DL_OK) {
        dl_bytes_destroy(&candidate);
        return status;
    }
    *out = candidate;
    return DL_OK;
}
```

There are three boundary cases. For a seven-byte file and an eight-byte cap, the read returns seven and sets end-of-file. For an eight-byte file and an eight-byte cap, it can return eight without having attempted to read past the end; the extra `fgetc` discovers EOF. For a nine-byte file and an eight-byte cap, that probe returns a real ninth byte, so the whole load fails instead of silently accepting a prefix.

The probe is an `int`, not a `char`. A real byte 255 and the negative `EOF` sentinel must remain distinguishable. `unsigned char` storage then promotes byte values 128–255 to positive integers when a batch is filled. A plain signed `char` array could turn those same bytes into negative values before conversion to `size_t`.

The payload allocation is bounded by `limit`, while the routine may consume `limit + 1` logical bytes to detect oversize input. The standard library may buffer additional physical I/O. This is not an adversarial network or device reader: use stable, ordinary local files, not an endlessly blocking source. On any rejection, the candidate is freed and the caller's owner is unchanged.

The path-based wrapper must check close **before** publishing the candidate. `fclose` can report an error, and the stream must not be used again even when closing fails; see the [close reference][fclose]. If reading already failed, that first error remains the diagnostic, but closing is still attempted.


```c title="src/data.c"
DlStatus dl_bytes_load(DlByteData *out, const char *path, size_t limit)
{
    if (out == NULL || path == NULL || limit < 2) return DL_ARGUMENT;
    if (!data_empty(out)) return DL_STATE;
    FILE *stream = fopen(path, "rb");
    if (stream == NULL) return DL_STATE;
    DlByteData candidate = {0};
    DlStatus status = dl_bytes_read(&candidate, stream, limit);
    if (fclose(stream) != 0 && status == DL_OK) status = DL_STATE;
    if (status != DL_OK) {
        dl_bytes_destroy(&candidate);
        return status;
    }
    *out = candidate;
    return DL_OK;
}
```

Notice that the wrapper does not pass the caller's owner straight into `dl_bytes_read`. Doing so would expose a successful read before the later close check. Keeping a second local candidate makes the entire path-based call transactional with respect to the output owner. This does not promise crash durability or protection from a file changing concurrently; those are outside this local loader's contract.

## Allocate the batch without unchecked products

The batch constructor computes $BT$, then $2BT+B$, then the byte size. Each step uses the checked helpers from Chapter 4. The stored views are derived only after allocation succeeds. `malloc` does not initialize the integer values; do not read a newly constructed batch until a fill call has succeeded.


```c title="src/data.c"
static int batch_empty(const DlByteBatch *b)
{
    return b->storage == NULL && b->ids == NULL && b->targets == NULL &&
           b->starts == NULL && b->batch == 0 && b->time == 0 && b->count == 0;
}

void dl_byte_batch_destroy(DlByteBatch *b)
{
    if (b == NULL) return;
    free(b->storage);
    *b = (DlByteBatch){0};
}

DlStatus dl_byte_batch_create(DlByteBatch *out, size_t batch, size_t time)
{
    if (out == NULL || batch == 0 || time == 0) return DL_ARGUMENT;
    if (!batch_empty(out)) return DL_STATE;
    size_t count, twice, elements, bytes;
    DlStatus status = dl_size_mul(batch, time, &count);
    if (status != DL_OK) return status;
    status = dl_size_mul(count, 2, &twice);
    if (status != DL_OK) return status;
    status = dl_size_add(twice, batch, &elements);
    if (status != DL_OK) return status;
    status = dl_size_mul(elements, sizeof(size_t), &bytes);
    if (status != DL_OK) return status;
    size_t *storage = malloc(bytes);
    if (storage == NULL) return DL_ALLOC;
    *out = (DlByteBatch){storage, storage, storage + count, storage + twice,
                         batch, time, count};
    return DL_OK;
}
```

The destination's `ids` view begins at element zero, `targets` at element `count`, and `starts` at element `2*count`. The earlier arithmetic proves that all three regions fit. Destruction frees only `storage`; freeing `targets` or `starts` would attempt to free interior addresses. Unlike returning three unrelated allocations, one owner also eliminates partial-batch-allocation cleanup.

An existing batch cannot be resized by calling the constructor again. Destroy it explicitly and construct a new one. The same rule applies to the loaded file owner. Silent replacement would obscure who loses the old allocation and whether saved references remain usable.

## Draw a uniform start without floating-point scaling

Training will sample valid starts **with replacement**. Two rows may overlap, or even be identical. This is not an epoch permutation and does not guarantee that every byte is visited. Uniform starts also do not imply uniform exposure of every target byte: targets near an edge belong to fewer possible windows. We keep this straightforward sampling objective rather than silently equating it to an exhaustive pass.

Chapter 12's generator produces a 64-bit word. Taking `word % W` is only unbiased when $W$ divides the number of possible words. Consider a four-bit analogue: 16 possible words reduced modulo 6. Residues 0, 1, 2, and 3 occur three times each, while residues 4 and 5 occur twice. More trials will not repair that imbalance.

Let $R=2^{64}$ and let

$$
a=R\bmod W.
$$

Reject words below $a$. The accepted interval $[a,R)$ has length $R-a$, which is an exact multiple of $W$. Consecutive integers over that many complete cycles contain each remainder equally often. Return the accepted word modulo $W$. For the four-bit example, reject 0–3 and retain 4–15: all six residues now have two representatives.

The derivation assumes uniformly distributed source words; it removes the additional bias from range reduction, not the statistical limitations of a deterministic generator. The [bounded-random discussion by O'Neill][bounded] gives the same rejection principle and alternatives. SplitMix64 remains the course's non-cryptographic reproducible generator.

The number $2^{64}$ cannot be stored in a `uint64_t`, but unsigned subtraction wraps modulo $2^{64}$. For nonzero $W$, `(UINT64_C(0) - W) % W` equals $2^{64}\bmod W$. This is defined unsigned arithmetic, not signed overflow. Reject zero before taking the remainder.

Replace the RNG header with this complete version. The only interface addition is `dl_rng_bounded`; its status type comes from `dl/common.h`.


```c title="include/dl/rng.h"
#ifndef DL_RNG_H
#define DL_RNG_H

#include "dl/common.h"
#include <stdint.h>

typedef struct { uint64_t state; } DlRng;

/* rng is nonnull, initialized with ANY uint64_t seed, and exclusively owned.
 * Deterministic non-cryptographic stream. No allocation or global state. */
uint64_t dl_rng_next(DlRng *rng);
/* One draw; 53-bit grid in [0,1), represented exactly in binary64. */
double dl_rng_uniform(DlRng *rng);

/* Rejection sampling in [0,bound); no float conversion or modulo bias.
 * Nonzero bound, nonnull independent rng/out. Invalid arguments change neither.
 * A successful call can consume more than one generator word. */
DlStatus dl_rng_bounded(DlRng *rng, uint64_t bound, uint64_t *out);

#endif
```

The earlier generator and floating uniform routine remain byte-for-byte unchanged. They are repeated here so the replacement source is complete; model initialization still consumes the same stream as before.


```c title="src/rng.c"
#include "dl/rng.h"

/* SplitMix64 mixing constants and recurrence: Sebastiano Vigna (2015),
 * public domain. https://prng.di.unimi.it/splitmix64.c
 * State is explicit here rather than a file-scope variable. */
uint64_t dl_rng_next(DlRng *rng)
{
    rng->state += UINT64_C(0x9e3779b97f4a7c15);
    uint64_t z = rng->state;
    z = (z ^ (z >> 30)) * UINT64_C(0xbf58476d1ce4e5b9);
    z = (z ^ (z >> 27)) * UINT64_C(0x94d049bb133111eb);
    return z ^ (z >> 31);
}

double dl_rng_uniform(DlRng *rng)
{
    return (double)(dl_rng_next(rng) >> 11) * 0x1.0p-53;
}
```

Append the bounded draw. Its output and generator must be independent objects. Valid arguments leave no failure path inside the loop, but a rejection can consume more than one word. Replaying only a call count is therefore less direct than saving the actual generator state.


```c title="src/rng.c"
DlStatus dl_rng_bounded(DlRng *rng, uint64_t bound, uint64_t *out)
{
    if (rng == NULL || out == NULL || bound == 0) return DL_ARGUMENT;
    /* Unsigned subtraction wraps modulo 2^64: threshold = 2^64 % bound. */
    uint64_t threshold = (UINT64_C(0) - bound) % bound;
    uint64_t word;
    do {
        word = dl_rng_next(rng);
    } while (word < threshold);
    *out = word % bound;
    return DL_OK;
}
```

For our file caps, rejections are very rare. That makes a test that merely samples ordinary windows a poor test of the rejection branch. Part 2 uses the legitimate bound $2^{63}+1$ and a known seed whose first word is rejected. That test does not allocate a huge file; it exercises the scalar range reducer directly.

Multiplying `dl_rng_uniform()` by $W$ is not a substitute for this derivation. That floating routine has a 53-bit grid; truncating a scaled finite grid can also distribute grid points unevenly. Use the integer routine for integer source offsets and reserve the floating routine for the numerical roles already defined.

## Copy exactly one extra byte into the target relation

Return to `src/data.c`. The preflight checks the actual constructor states and verifies $N>T$. It deliberately relies on the established metadata invariants rather than accepting arbitrary user-written dimensions. `copy_window` is private: its callers have already proved the source interval and destination row are valid.


```c title="src/data.c"
static DlStatus batch_check(const DlByteData *d, const DlByteBatch *b)
{
    if (d == NULL || b == NULL) return DL_ARGUMENT;
    if (d->bytes == NULL || b->storage == NULL) return DL_STATE;
    /* Other fields are the established constructor invariants, not user input. */
    if (d->count <= b->time) return DL_RANGE;
    return DL_OK;
}

static void copy_window(const DlByteData *d, DlByteBatch *b,
                         size_t row, size_t start)
{
    b->starts[row] = start;
    size_t base = row * b->time;
    for (size_t t = 0; t < b->time; ++t) {
        b->ids[base + t] = d->bytes[start + t];
        b->targets[base + t] = d->bytes[start + t + 1];
    }
}
```

The two assignments are the entire target transformation. There is no string length, character decoding, terminator search, or extra tokenizer offset. Every source byte is promoted from `unsigned char` into `size_t`, so every ID stays in 0–255. The file is read-only while batches are built.

Sampling uses a copy of the caller's random state. Structural rejection happens before any batch writes or random draws; then the prevalidated bounded calls cannot fail. On success, the final state is committed. This design leaves a clear next-batch state for later checkpointing without implementing checkpoint I/O here.


```c title="src/data.c"
DlStatus dl_byte_batch_sample(const DlByteData *d, DlByteBatch *b, DlRng *rng)
{
    if (rng == NULL) return DL_ARGUMENT;
    DlStatus status = batch_check(d, b);
    if (status != DL_OK) return status;
    uint64_t bound = (uint64_t)(d->count - b->time);
    DlRng candidate = *rng;
    for (size_t row = 0; row < b->batch; ++row) {
        uint64_t start;
        /* These validated arguments make the bounded draw infallible. */
        status = dl_rng_bounded(&candidate, bound, &start);
        if (status != DL_OK) return status;
        copy_window(d, b, row, (size_t)start);
    }
    *rng = candidate;
    return DL_OK;
}
```

Use a data RNG independent of the model's initialization state. Two separately owned generators can have fixed seeds, but they must not be one shared mutable object. Changing model width should not silently change the future training windows by consuming a different number of initialization draws. Similarly, validation should not advance the training generator.

A successful sample fills all three batch regions. A preflight error leaves the previous successful batch and generator state intact. There is no automatic retry with a shorter sequence: silently reducing $T$ would change the workload and objective while hiding the actual short-file error.

## Traverse validation without wrapping or padding

An ordered iterator holds a cursor pointing to the first input byte of the next row. For a full batch it consumes $BT$ **target positions**, so the cursor advances by that amount. Adjacent rows share a boundary byte between a target and the next input, but their target positions are disjoint.

For initial cursor zero, the number of scored targets in complete batches is

$$
Q=BT\left\lfloor\frac{N-1}{BT}\right\rfloor,
\qquad U=(N-1)-Q.
$$

$U$ is the number of unscored trailing target positions. With eight bytes, $B=2$, and $T=3$, $Q=6$ and $U=1$. Neither an extra zero token nor a wrapped source byte is a valid way to fill that tail. Future evaluation will report the actual count; using $B=1$ can reduce the discarded tail to fewer than $T$ targets without changing model weights.


```c title="src/data.c"
DlStatus dl_byte_batch_next(const DlByteData *d, DlByteBatch *b,
                            size_t *cursor, int *has_batch)
{
    if (cursor == NULL || has_batch == NULL) return DL_ARGUMENT;
    DlStatus status = batch_check(d, b);
    if (status != DL_OK) return status;
    if (*cursor > d->count - 1) return DL_RANGE;
    if (b->count > d->count - 1 - *cursor) {
        *has_batch = 0;
        return DL_OK;
    }
    for (size_t row = 0; row < b->batch; ++row)
        copy_window(d, b, row, *cursor + row * b->time);
    *cursor += b->count;
    *has_batch = 1;
    return DL_OK;
}
```

The order of the bounds checks matters. `*cursor > count - 1` is rejected before subtracting the cursor. The second test uses the remaining count, avoiding `cursor + batch.count` overflow. Once that test passes, every copied start and final target address fits, and the cursor increment is safe.

An exhausted iterator returns `DL_OK` with `has_batch=0`, preserving both cursor and batch. A caller must check that flag: the old batch bytes still exist but must not be counted again. An invalid cursor returns an error and leaves even `has_batch` unchanged. Keeping normal exhaustion separate from malformed state makes the future evaluation loop unambiguous.

The iterator has no RNG parameter, so evaluating validation cannot consume the training random stream. It also has no second file parameter: a window cannot accidentally straddle the end of training and beginning of validation inside this implementation. The caller must still supply the intended file. A filename is not proof of provenance; Part 2 creates the two files from distinct source splits and records that mapping.

## Show bytes without executing their terminal controls

Printing arbitrary data with `%s` has two problems: a loaded file is not null-terminated, and embedded zero bytes end a string early. Even a length-bounded raw print can emit terminal escape sequences or malformed UTF-8. Our display function emits only printable ASCII plus explicit escapes, enclosed in quotes. It does not alter the original data.


```c title="src/data.c"
DlStatus dl_bytes_fprint(FILE *stream, const unsigned char *bytes, size_t count)
{
    if (stream == NULL || (bytes == NULL && count != 0)) return DL_ARGUMENT;
    if (fputc('"', stream) == EOF) return DL_STATE;
    for (size_t i = 0; i < count; ++i) {
        unsigned int c = bytes[i];
        const char *escape = NULL;
        if (c == '\n') escape = "\\n";
        else if (c == '\r') escape = "\\r";
        else if (c == '\t') escape = "\\t";
        else if (c == '\\') escape = "\\\\";
        else if (c == '"') escape = "\\\"";
        if (escape != NULL) {
            if (fputs(escape, stream) == EOF) return DL_STATE;
        } else if (c >= 32 && c <= 126) {
            if (fputc((int)c, stream) == EOF) return DL_STATE;
        } else if (fprintf(stream, "\\x%02X", c) < 0) return DL_STATE;
    }
    if (fputc('"', stream) == EOF || ferror(stream)) return DL_STATE;
    return DL_OK;
}
```

The classification is deliberately locale-independent: ASCII values 32–126 are printable, except that backslash and quote must be escaped. Common controls use `\n`, `\r`, and `\t`; all other values use two hexadecimal digits. A real newline byte and the two literal bytes backslash-plus-`n` therefore display differently. The function is a presentation notation, not a C source-code serializer or a UTF-8 repair tool.

Each output operation is checked. An output error can leave a partial quoted display, because bytes already written to an external stream cannot be retracted. The caller owns flushing and closing; a buffered write can appear successful until a later flush. The inspection application in Part 2 checks its final `fflush(stdout)` before reporting success.
